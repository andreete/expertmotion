## 0. How to read this document

- One row = one functional requirement. **Status is `planned` for every FR** in this baseline and is therefore not repeated per row.
- **Trigger** cites Element IDs from ELEMENT_IDS.md (`el:` prefix omitted inside tables for width; `hdr.menu.file.new` means `el:hdr.menu.file.new`).
- **Agent involvement** is exactly one of: `deterministic — no LLM` (code only, no Edit Intent or a non-edit action), `Edit Intent → Compile` (typed Edit Intent compiled into Operations without an LLM; applied immediately, recorded in the Intent Queue, creates a Composition Version, AI-004), `Edit Intent → Editor Agent` (typed Edit Intent with `needsInterpretation: true`, Rewrite, Edit Plan, Creator presses Execute).
- **Intent** gives the Edit Intent `category / propertyKey pattern / propertyClass` using the AI_WORKFLOW.md vocabulary, and the Operation(s) the Compile path emits. `—` when no Edit Intent is produced.
- **Errors** cite ERROR_CATALOGUE.md codes. **Undo / recovery** states what reverts the action (Composition Version = undo via FR-167; "n/a" when nothing is mutated).
- **Priority** is MoSCoW (M/S/C/W) plus the PRD tier (P0/P1/P2). Every P0 item is Must.
- **Acceptance** is Given / When / Then compressed into one cell (`G:` / `W:` / `T:`). TEST_PLAN.md turns each into ≥ 1 `QA-` case.
- **Verif.** = verification method: `unit` (pure function tests), `int` (service integration test with fakes), `e2e` (Editor UI test with `data-el` selectors), `vm` (manual test on a clean Windows VM), `measure` (instrumented measurement per PERFORMANCE.md), `review` (design/code review).
- Every user-facing string named in this document has an EN and an ID variant in ERROR_CATALOGUE.md or UI_UX_SPECIFICATION.md; this document quotes EN with the ID variant in parentheses only where the string is defined here for the first time.
- Concepts owned elsewhere are referenced, not redefined: schemas (AI_WORKFLOW.md, DATABASE_SCHEMA.md), presets (DESIGN_CATALOGUE.md), element ids (ELEMENT_IDS.md), pixel table and profiles (PERFORMANCE.md), licence format (LICENSE_OPERATIONS.md), security controls (SECURITY.md).

### 0.2 Cross-cutting functional rules (apply to every FR)

| Rule | Statement | Source |
|---|---|---|
| X-1 | Nothing mutates the Composition Model except (a) Execute of a valid Edit Plan and (b) Compile of a fully specified Edit Intent; both create an immutable Composition Version. | AI-004, ADR-002 |
| X-2 | Every mutation is undoable by moving the project head to the previous Composition Version (FR-167). Destructive actions (remove clip, remove asset in use, reset, restore, replace) ask for confirmation first. | brief §7.1 "never silently overwrite" |
| X-3 | Every failure shows ERROR_CATALOGUE.md copy with a recovery button; stack traces never reach the UI. | PRD-015 |
| X-4 | Every FR that reaches a provider shows "Asking <model>…" ("Menanyakan <model>…") while the request runs, and is disabled in Private Mode with EM-4401 / EM-8202. | AI_WORKFLOW §11, §12 |
| X-5 | All UI actions are keyboard reachable; focus order follows the wireframe reading order (SRS NFR-082). | ACCESSIBILITY_AND_I18N.md |
| X-6 | The Editor never computes Composition Model state locally; it displays what the Local Service sends over SSE (`composition.updated`, `intent.updated`, `plan.ready`, `render.progress`). | ARCHITECTURE §3 |
