This document states what Expertmotion must do to be secure and how each control is verified. It references, never redefines: terms are in `GLOSSARY.md`, the process model in `ARCHITECTURE.md` §5, storage in `DATABASE_SCHEMA.md`, the licence format in `LICENSE_OPERATIONS.md`, error codes in `ERROR_CATALOGUE.md` (EM-6xxx storage, EM-7xxx models, EM-8xxx shell/service/updater/network/Private Mode). Threats are in `THREAT_MODEL.md`; the per-release pass/fail list is `VULNERABILITY_CHECKLIST.md`.

Boundary statement (ADR-006, ADR-007): every control below **raises the cost of extraction or misuse**. None of them protects against the owner or an administrator of the computer with a debugger, a patched binary, or a compromised operating system. `THREAT_MODEL.md` §6 lists what is not protected.

Sources confirmed on 2026-10-24: Electron security checklist https://www.electronjs.org/docs/latest/tutorial/security; fuses https://www.electronjs.org/docs/latest/tutorial/fuses; ASAR integrity https://www.electronjs.org/docs/latest/tutorial/asar-integrity; `safeStorage` https://www.electronjs.org/docs/latest/api/safe-storage; `utilityProcess` https://www.electronjs.org/docs/latest/api/utility-process; `contextBridge` https://www.electronjs.org/docs/latest/api/context-bridge; `protocol` https://www.electronjs.org/docs/latest/api/protocol; `session` https://www.electronjs.org/docs/latest/api/session; Remotion Electron guide https://www.remotion.dev/docs/electron; Remotion licensing/telemetry https://www.remotion.dev/docs/licensing; electron-updater https://www.electron.build/docs/features/auto-update; Windows code-signing options https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/code-signing-options.

| Column | Meaning |

## 1. Local Service (ADR-005)

The Local Service is reachable by any process or web page on the same computer that can open a loopback socket. Localhost binding is not a security boundary (brief §12). The Service Token is.
